# 网页端侧栏样式打磨

状态：已实现并验收（2026-10-31，用户要求 Claude Code 直接实现，分支 `web-sidebar-polish`）。只改样式和侧栏的几处 DOM 组装，不改数据、接口、交互逻辑。

用户确认时追加一条：收起侧栏的按钮和收起后的展开按钮“割裂”（一个在侧栏右上角、图标是侧栏，一个在顶栏最左、图标是三条横线），一起改成同一个按钮（第 1 项）。三个待确认问题按建议定：叫“新任务”、收起按钮常显、选中行加粗。

## 为什么要改

用 `qa` 账号在 1400×900 下截了侧栏（浅色、深色、选中一条对话、展开“工具与更多”），并用脚本量了各元素的位置（侧栏宽 300px，下文坐标都是 CSS px，相对侧栏左边）。问题集中在“没有对齐、层级不统一”，不是缺功能：

| # | 现象 | 量到的数 / 原因 |
| --- | --- | --- |
| 1 | 顶部铃铛、搜索两个图标离右边很远，右侧空出一块 | 第三个按钮“收起侧栏”平时 `opacity:0`（`layout.css:15`），仍占 260–287；看得见的图标止于 258，而下面各行右边到 291 |
| 2 | `tern` 字标和下面各行的左边不齐 | 字标从 12 开始（`.brand` 的 `padding-left:12px`），各行图标从 18 开始，头像从 16 开始 |
| 3 | “新聊天”和“项目”之间空得很大 | `.navlabel` 的 `padding-top:24px`，标题行高 58 |
| 4 | “项目”和“对话”两个分区标题长得不一样：“项目”是深色、文字从 27 开始，“对话”是灰色、从 18 开始 | `layout.css:27` 本想把筛选菜单的标题改成灰色、无内边距，但 `.chrome-menu > summary`（`layout.css:52`）选择器权重相同、写在后面，把它覆盖了 |
| 5 | 项目名 `tern` 是灰色，像被禁用；对话标题是深色 | `.project-group > summary` 颜色取 `--muted`；项目行高 41，对话行高 38 |
| 6 | 项目行的文件夹图标比对话行的图标往右缩了 16px，图标列不成一条线 | 项目行前面先画了展开箭头（`::before`），文件夹图标落在 34，对话图标在 18 |
| 7 | 未读蓝点悬在行中间偏右，离右边 38px | 点在 247–253；后面隐藏的“⋯”按钮（`opacity:0`）仍占 259–281 |
| 8 | 底部“工具与更多”和“设置”不像同一组：一个是灰字配箭头，一个是深色配图标；文字起点也不同 | “工具与更多”用旋转的边框画箭头当图标，`--muted` 13px；“设置”是 `--text` 14px |
| 9 | 点开“工具与更多”，触发它的那一行跳进弹层顶部，变成灰色小标题 | 打开时整个 `<details>` 变成 `position:absolute`（`layout.css:44`），summary 跟着进了弹层 |
| 10 | 活动铃铛的未读点颜色写死 `#3783ff`，深色模式下和其它未读点（`--accent`）不一样 | `layout.css:18` |

另外同类规则在 `app.css` 和 `layout.css` 里来回覆盖（如 `.project-group > summary` 在 `app.css:831`、`layout.css:29`、`layout.css:327` 三处），第 4 条就是这样出的错。

## 改成什么样

统一一套网格，所有行都按它对齐：

- 行：左右各留 8px（`margin: 0 8px`），行内 `padding: 0 10px`，行高 34px，圆角 8px。
- 图标列：x = 18，16×16，颜色 `--muted`。
- 文字列：x = 42（图标 16 + 间距 8），14px，颜色 `--text`。
- 行右端的操作位（⋯、＋、未读点）：右边对齐到 281（行右边 291 减内边距 10），宽 22。
- 分区标题（“项目”“置顶”“对话”、多主机时的主机名、“已归档（N）”）：一种样式，12px、`--faint`、字重 500，文字从 18 开始，上间距 16、下间距 4。

逐项：

1. **顶部与收起/展开**：顶部一行高 56，和顶栏同高。收起侧栏的按钮挪到最左（按钮 28×28，左 12，图标在图标列 18），字标 `tern` 跟在后面、落在文字列 42；右边是活动、搜索两个按钮，常显，图标中心和下面各行的“⋯”对齐（270）。收起以后，顶栏的 `#menu` 用同一个侧栏图标、出现在同一个位置（左 12、上 14），点它展开；窄屏抽屉里也一样（顶部 52 高，和窄屏顶栏同高）。原来平时透明的收起按钮（`layout.css:15–16`）去掉。
2. **新聊天**：样式不变（就是一行），和下面分区的间距按分区标题的上间距 16 走，去掉 `.navlabel` 的 `padding-top:24px`。
3. **“项目”分区标题**：筛选菜单的 summary 改成分区标题的样式（灰色、文字在 18、无底色），后面的小箭头 10px；悬停时文字变 `--text`。右边的“＋”换成 `chromeIcon("plus")`（16px 图标、22px 按钮），右边对齐到 281。修第 4 条的办法：把侧栏专用的规则写成 `#sidebar .sidebar-filter-menu > summary`，不靠书写顺序。
4. **项目行**：行高、字号、颜色和对话行一样（`--text`）。图标列放文件夹图标；展开/收起的箭头不再单独占一列，改成鼠标悬停（或键盘聚焦）这一行时，图标列的文件夹换成箭头（展开朝下、收起朝右），离开再换回文件夹。右边的“⋯”照旧悬停才出现。
5. **项目下的任务**：不画对话图标，文字和项目名对齐在 42（`padding-left: 34px`，去掉 `margin-left: 12px`）。空项目的“还没有任务”同样从 42 开始，12px、`--faint`，上下各 4px。
6. **不属于项目的对话**：保持现在的对话图标 + 标题，只按网格对齐。
7. **未读点与“⋯”共用右端的操作位**：平时操作位显示未读点（居中在操作位里，即点的中心约在 270），悬停或选中这一行时点隐藏、显示“⋯”。没有未读的行，平时操作位是空的。时间（`small`）照旧悬停显示，放在操作位左边。
8. **底部**：“设置”“工具与更多”两行同一样式。“工具与更多”换成真正的图标（在 `layout.js` 的 `paths` 里加一个 `more`：三个横排的点），文字 `--text` 14px。
9. **“工具与更多”弹层**：summary 留在原地不动，打开时这一行带 `--hover` 底色表示按下；弹层单独一层，左右和行对齐（left 8、宽 284），底边在这一行上方 4px。弹层里去掉重复的“工具与更多”小标题；最后一行“外观”上面加一条 `--line` 分隔线。要做到 summary 不动，`layout.js` 里把这些按钮和外观选择装进一个 `div.nav-tools-menu`，绝对定位的是这个 div，不是整个 `<details>`。点弹层外面或按 Esc 关掉（现在点外面不关的话，一起补上）。
10. **账号行**：头像的中心对齐图标列的中心（头像左边 14），用户名 13px `--muted`；“退出”照旧悬停显示，右边对齐到 281。
11. **颜色**：活动未读点改用 `var(--accent)`。选中行 `--sel`（#e9e9eb）和悬停 `--hover`（#ededee）在浅色下几乎分不出来：选中行字重改 500，底色不变。

深色模式不另写规则，全部用变量。窄屏（≤760px）抽屉里的侧栏宽 270，按同一套网格，右端坐标随宽度变，不写死。

## 这一期不做

- 不改侧栏宽度、不加拖动改宽。
- 不改信息结构：不挪“设置”的位置，不把“工具与更多”里的入口拆出来，不改“项目”“对话”的分组规则。
- 不清理 `app.css` 里被覆盖的旧侧栏规则（以后整体清 CSS 时再做）。
- 顶栏、输入框、右侧工作区的样式不在这份里。

## 实现记录（2026-10-31）

- `layout.js`：`paths` 加 `more`；收起按钮 `prepend` 到 `.brand` 最前，`#menu` 换成同一个 `sidebar` 图标（类名 `chrome-icon sidebar-toggle`，标题“展开侧栏”）；“＋”用 `chromeIcon("plus")`；“工具与更多”的 summary 加图标，其余子元素和外观选择装进 `div.nav-tools-menu`。点外面、Esc 关弹层原来就有（`.nav-tools[open]` 已在关闭逻辑里），没有另加。
- `shell.js`：`projectGroup` 的图标位换成 `span.proj-ico`（文件夹 + 箭头两个 svg）。未读点在 `runRow` 里插在“⋯”前、刷新时追加在“⋯”后，顺序不一，改用 CSS `order` 固定，DOM 没动。
- `layout.css`：第 10–47 行旧的侧栏规则换成一整块 `#sidebar` 开头的规则；删掉项目箭头、“工具与更多”箭头、归档箭头的旧规则和 `.sidebar-collapsed #menu`。
- 验证：网页端的页面是编进程序的，为了不替换正在跑的 app-server，没有重启网页端，而是用 Playwright 连现有的网页端、把 `/ui/` 下的文件换成工作区里的（`route.fulfill`）。量得：图标列都在 18、文字列都在 42、分区标题文字在 18 且样式相同；“＋”、“⋯”、未读点、右上按钮的中心都是 270；项目行与对话行都高 34；打开“工具与更多”前后触发行的位置不变、弹层里没有重复标题，Esc 和点外面都能关；收起前后切换按钮都在 (12, 14)，窄屏抽屉内外都在 (12, 12)；观测页勾选框在 18、标题被推到 61，不压字。浅色、深色、选中、悬停项目行、窄屏截图人工看过。`node --check`、`go build ./...`、`go vet ./internal/web/` 通过。
- 没有覆盖到：多主机分组、置顶、已归档、项目下有任务的情况（qa 账号当前没有这些数据），这几处只按 CSS 推算。

## 验收

1. `node --check internal/web/page/layout.js internal/web/page/shell.js`；`go build ./...`。
2. 起网页端，用 `qa` 账号登录（`.env` 里的 `TERN_QA_USER`、`TERN_QA_PASSWORD`），准备：一个有任务的项目、一个空项目、一条不属于项目的未读对话、一条已归档的对话。
3. 在 1400×900 下用 Playwright 量位置（脚本放临时目录，不提交），预期：
   - 字标、所有行的图标（新聊天、文件夹、对话、设置、工具与更多）左边都是 18±1；头像中心和图标中心的横坐标差 ≤1。
   - 项目名、不属于项目的对话标题、项目内任务标题、“还没有任务”、新聊天/设置/工具与更多的文字左边都是 42±1。
   - “项目”“对话”“已归档”等分区标题文字左边都是 18±1，颜色、字号、字重相同（取 computed style 比较）。
   - 顶部最右边那个按钮的右边、“＋”的右边、每行“⋯”的右边都是 281±1；未读点中心和同一行“⋯”中心的横坐标差 ≤1。
   - 项目行与对话行高度相同，项目名颜色等于对话标题颜色。
   - 打开“工具与更多”前后，它那一行的 `getBoundingClientRect().top` 不变；弹层里不再出现“工具与更多”四个字；按 Esc、点弹层外面都能关掉。
4. 截图对照（浅色、深色、选中一条对话、悬停项目行、打开“工具与更多”、窄屏 700×900 打开抽屉），人看一遍没有错位和溢出。
5. 观测页（`对话 / 观测` 切到观测）侧栏的勾选框仍可勾选对比，位置不压文字。

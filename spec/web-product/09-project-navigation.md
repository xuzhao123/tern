# 项目树、个人置顶与执行上下文实现

状态：开发中；对应 NAV-01/02/03、CTX-01，验收 A01/A02/A03 的有关部分。

项目身份按执行主机内登记的绝对目录生成稳定摘要，前端再加主机命名空间。显示名只作标签，改名不改变 ID；副本任务以 copy_of 关联原项目，实际执行目录仍为副本。历史任务从已有 workspace_dir/copy_of 快照推导 ID，没有目录证据时保留独立“历史项目”组，不按同名猜测。现有事件不改写，ID 计算不写磁盘，因此无需破坏性数据迁移；读回列表即为迁移映射报告。

新增 `workspace/list`（HTTP `GET /workspaces`）提供 ID/name/path/git；任务摘要增加 workspace_id/workspace_dir/project_dir。旧字段和链接不变。设置的 workspaces 回复也附 ID，便于新任务选择与任务树共用。

新增 `thread/pin {threadId,pinned}`（HTTP `PUT /runs/{id}/pin`），严格接受布尔值；个人置顶存入 settings.json 的独立 thread_pins 用户映射，沿用 hubMu 与原子写入。web 由已登录账号注入 user；直接协议遵循已有本地主人信任边界。列表按当前用户返回 pinned，原元数据和归档语义不变。恢复旧程序可能不认识新偏好字段，降级前须保存设置文件，不能声称旧程序能编辑新偏好。

前端按主机/项目目录展示可折叠项目树，包含已登记但无任务的项目；保留最近任务、置顶、归档入口。项目行提供新任务、改名和移除；跨主机新建先导航目标主机再选项目。移除仅解除登记，历史任务和目录不删除。主机失联时显示不可用，不显示为空项目或自动跳本机。

按文件改动：appserver/settings.go（项目 ID/list/个人置顶存储）、server.go（任务摘要/用户列表）、threads.go（pin）、handle.go；web/server.go（代理路由）、page/shell.js（树/菜单/上下文）、main.js（账号与初始项目）、index.html/app.css。目录身份不等同 Git 分支；Git 实时状态在后续工作面板中补足，不伪造分支或干净状态。

验收：隔离实例注册两个同名 basename 的不同目录，创建真实任务后改名，验证 ID、树归属、历史执行目录不变；副本任务仍关联原项目；无目录历史不合并；两账号的 pin 分离，重启保持；缺失主机/目录明确报错；静态检查、构建和真实浏览器回归。未通过上述全部场景前不关闭对应完整产品需求。

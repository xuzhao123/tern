# 草稿、发送回执与事件流恢复

状态：开发中，对应 CHAT-03、CHAT-02 的发送基础、UX-03，验收 A06/A07/A11/A12。不替代服务端队列编辑排序与 Goal 调度。

## 草稿

浏览器按账号、执行主机、任务 ID 保存草稿；新任务按项目目录身份区分。内容是未发送文字、已上传附件引用与输入选择，不保存模型密钥和附件二进制。切任务/新任务/打开设置前保存，恢复不自动发送。持久化失败显示错误并在离开前提醒；账号未确定前不读写其他账号草稿。

每份草稿带版本与页面作者 ID。多标签页发生并发修改时保留本地内容和远端版本，要求选择保留/合并，不静默覆盖。附件引用需重新检查是否可读；失效时明确保留文件名并提供移除，不偷偷丢失。退出账号不把草稿暴露给下一账号。

网页 API 请求携带当前页面认识的账号名，服务端只与已认证账号比较，不将该字段当凭证。另一个页面切换账号后，旧页面请求返回明确的账号变化错误，保存旧账号草稿再刷新，防止旧输入以新账号继续发送。旧客户端不带此兼容字段时仍沿原认证逻辑。

## 普通发送与回执

`thread/start`、`turn/start` 接受可选 `request_id`，旧客户端不带时保留原行为。新客户端提交前持久化相同请求 ID 与负载；服务端按账号 + ID 原子认领，并记录请求方法和规范化负载摘要。相同 ID 不同负载拒绝，相同请求只执行一次。

新增 `request/status {request_id}`，web 为 `GET /requests/{id}`。返回 accepted（含原响应）、rejected（含原错误）、pending（处理中或状态待确认）、not_found。回执存 `.data/requests/`，权限 0600，写入失败不得先执行。执行完成后保存响应；start/continue 事件同时保存 request_id/request_user，进程崩溃落在事件与回执之间时可从已有事件恢复关联，不重新执行。

pending 且没有可靠事件时不自动重试或判定未接收；保持待确认并保留草稿。accepted 只说明接收，不说明任务成功。仅在查询明确 not_found 且用户显式重试时复用同一 ID/负载，避免查询后到达的迟发请求被重复派发。

## 浏览器恢复

事件流支持 after 序号并输出 SSE id。浏览器断线重连携带最后确认序号，忽略已应用事件，保留草稿与阅读状态；不能把连接中断当作 agent 已终止。切任务后旧重连计时器不能再更新当前任务。无权限/任务删除应终止重连并给真实原因。

# 子 agent：分工、进度、结果与干预

状态：已纳入产品范围，部分开发中；当前状态与证据见 [实现记录](08-implementation.md)。2026-10-25 补充；用户反馈“subagent 的体验也不太好”。现状基线仍为 `6fba4ad`。这份方案是 Tern 的目标体验，不将建议的按钮和状态说成 Codex 已核实的具体界面。

## 1. 要解决的体验问题

用户不应该展开每一个工具调用，才能回答这些问题：谁在做什么、主 agent 在等谁、哪个需要我处理、结果在哪里、怎样只纠正其中一个任务。

当前已经有子 agent 卡片、完整过程侧栏、后台执行、父 agent 等待/发送消息/停止/续跑能力。问题集中在这些能力还没有组织成可理解、可干预的协作体验。**模型能调用控制工具，不等于网页用户已有直接控制入口。**

| 现状 | 体验影响 | 核对结论 |
| --- | --- | --- |
| 卡片按 spawn 调用排列，标题为“子 agent N”，主要信息是任务原文与请求次数 | 难以扫读分工，同一 task_id 续跑可能表现成另一张卡 | `agents.js` 的 `subList`、`agentCard`；后续按稳定子任务聚合、保留尝试记录 |
| `subState` 优先把 `res.status === "ok"` 显示为完成；后台 spawn 成功却只返回 `status: running` | 启动成功可能被误判为工作完成，误导父子进度 | 静态路径风险明确，需用真实后台任务复现；不能当作本轮已实测缺陷 |
| 详情固定写“看不到父对话”；后端已有 `fork: true` | 用户不能准确判断子任务已有上下文 | 文案与后端能力不一致；UI 必须显示实际模式，旧记录无法确认时写未知 |
| 详情以完整过程为主，结果依赖工具返回或流式内容 | 得逐段翻才能找到结论，难以判断主 agent 是否已经收到结果 | 需要独立结果摘要和回收状态，不重复创建一份普通聊天 |
| 子任务与 diff、文件、浏览器争用右侧面板 | 看进度容易失去当前阅读位置 | 复用统一工作面板，增加持久的父子导航与每个子任务的视图状态 |
| 后台子任务只活到父任务本轮结束 | 主 agent 收尾可能使仍在工作的子任务停止 | 必须显露生命周期；独立跨轮后台运行不属于本期 |

依据：[E19/E20](05-evidence.md#子-agent-补充核对)。上表记录立项时的静态核对；后续真实运行和局部修正见 08，不将局部验证等同完整场景通过。

| ID | 需求与可见结果 | 优先级 / 批次 | 实现边界 |
| --- | --- | --- | --- |

| SUB-08 | 失败、已停止或结果未知时提供可理解的恢复路径，沿用同一子任务身份 | P1 / B4 | 区分续跑与重新执行；完成存档回放不是重新计算；涉及副作用不盲重做 |

## 3. 页面与组件

主对话只保留轻量的协作卡片；需要审批/回答时可展开待处理条。子任务每一次 token、工具输出、等待轮询都不复制到主对话里刷屏。

```text
正在协作 · 3 个子任务          [查看全部]
● 检查登录流程   正在运行 · 正在读取配置
! 核对接口权限   等你审批 · 访问测试服务
✓ 检查回归用例   已完成 · 结果已返回
主任务：等待“检查登录流程”的结果
```

任务名来自结构化标题；缺少时从任务原文取短摘要并能展开全文。动作摘要只能来自真实活动或有来源的 agent 进展，不根据耗时编造“正在测试”。数量是子任务个数，不是工具调用次数，也不计算虚假的总体百分比或 ETA。

```text
工作面板 / 子任务
[← 返回主任务]   全部 3  运行中 1  待处理 1  已结束 1

检查登录流程                 ● 正在运行   已运行 2m
主机 dev · 项目 tern · 与主任务共享工作目录
上下文：独立任务说明（或：继承父对话的某次快照）
本轮结束时，仍运行的子任务将停止

[概览] [执行过程] [结果与产物]
任务：检查登录态失效时的跳转，不修改文件
最近进展：已定位到 auth.go，正在检查失败分支

补充说明…
[告诉主 agent]  [直接发给此子任务]  [停止此子任务]
```

上面的直接发送与停止是 B4 目标；B2/B3 只提供“告诉主 agent”的明确入口，加入带目标引用的主输入草稿，由用户发送后交给父 agent。**不能先显示“已直接通知子任务”，实际却只发到了父任务。** 后端能力未实现时，不出现无效按钮。

- 概览：分工、生命周期、执行位置、上下文来源、最近活动、待处理事项。
- 执行过程：复用现有工具/流式展示；原始参数、日志、调用 ID 放在详情层。
- 结果与产物：先展示子任务原始结论、文件/测试证据、未解决项，再链接具体过程。信息缺失就不生成假的通过徽标。
- 结果传递：标明“尚未回收 / 已返回主任务 / 状态未知”。如果父 agent 给出采用或不采用说明，可显示带来源的说明；不能以 agent_wait 成功推断已人工验收。
- 主 agent 汇总多个结果时保留来源链接；结果矛盾或失败的子任务不能在“全部完成”摘要中被隐藏。
- 返回主对话恢复原阅读位置；切换子任务保留各自标签、滚动、展开项和补充草稿。新进展不抢焦点。
- 窄屏用列表 → 详情 → 返回的单列路径，不在同屏压出多层小侧栏。

## 4. 状态与生命周期规则

执行状态、结果回收状态、连接状态是不同维度。界面不得用一次 spawn 工具返回来覆盖后续真实执行事件。

| 信号/场景 | 产品显示 | 禁止的推断 |
| --- | --- | --- |
| 派发请求已发出，尚未确认启动 | 启动中 | 不凭工具开始就显示正在改文件 |
| 后台 spawn 回 task_id + running | 正在运行 | 外层 `ok` 不等于子任务完成 |
| 子任务审批/回答仍未解决 | 等你审批 / 等你回答，并可定位 | 不只显示模糊的运行中 |
| 父 agent 显式等待一个或任意子任务 | 等待指定子任务 / 等待任一结果 | 等待超时不代表子任务失败 |
| 收到停止请求回执 | 正在停止 | 直到权威终止结果到达才显示已停止；超时显示待确认 |
| 子任务完成事件或可靠完成记录 | 已完成；结果回收状态单独显示 | 完成不等于测试全通过、父任务已采用或已提交 |
| 取回已完成存档 | 已完成 · 取回已有结果 | 不增加一次新的运行或生成新的子任务身份 |
| 父轮结束，子任务被收尾停止 | 已停止 · 主任务本轮结束 | 不标失败，也不宣传还在独立后台运行 |
| 断线/缺少终止记录/事件矛盾 | 状态待确认 + 最后确认时间 | 不能因父任务结束就凭空给所有子任务写成功 |

当前后台生命周期限定在父轮内；本期先准确展示，不偷偷改成跨轮常驻。用户“停止整个任务”应说明影响仍运行的子任务，逐项显示确认结果；“停止此子任务”不应停止兄弟任务，也不自动回退其已写文件。关闭网页或面板是界面行为，不等于主动停止；最终仍受父轮结束规则约束。

## 5. 干预与恢复

1. **告诉主 agent**：用户选择目标后，内容进入主任务输入草稿，包含稳定子任务引用；用户发送才成为父任务消息。明确这由父 agent 决定如何调整协作。
2. **直接补充子任务（B4）**：显示收件子任务，独立草稿与请求 ID；有“待接收/已接收/已采纳/未送达”回执。已完成的子任务不能假装收到；提供把内容交回父任务或显式续跑的选择。父任务有一条简短干预记录，避免不知子任务被改了方向。
3. **停止单个子任务（B4）**：命令目标包含父任务和子任务身份，防止同名误停；以实际退出为完成依据。与完成事件竞争时返回真实最终状态，不重复停止。
4. **续跑（B4）**：沿用 task_id，在其下追加一次执行尝试；检查点有效时继续，已完成时取回结果并明确标注。用户要重新计算时属于新的尝试，需解释可能重复副作用。
5. **审批与提问**：父任务待处理区显示“来自：子任务名称”；原请求失效后不再可点，两个页面同一请求只能处理一次。子任务输出不是用户授权。

直接控制不经浏览器启动新 agent 进程。所有动作走 web → app-server → 当前拥有子任务的父进程 → 子进程协议；必须核验目标归属、当前尝试、请求幂等和权限，保留现有审批/审计约束。不能拼一段命令让模型执行来冒充可靠的直控 API。

## 6. 数据与实现边界

| 变化点 | 已有基础 | 需要补足 |
| --- | --- | --- |
| 任务身份 | task_id、父 call_id、started/completed/message 事件 | 同一子任务跨调用与尝试聚合；父任务/父轮/来源关系持久化，旧历史不强行猜配 |
| 状态与上下文 | 事件、后台返回的 running/fork、子任务过程 | 实际上下文模式、停止原因、等待对象、结果回收事件；未知字段允许为空 |
| 结果 | 子任务结论、agent_wait 返回、存档回放 | 稳定的结果入口及来源；生命周期和取回结果分开 |
| 网页直控 | 父 agent 已有 agent_send/agent_stop 与子协议连接 | web/app-server 的认证转发、去重、目标校验、回执、父任务知情事件；不能只调用不存在的接口 |
| 目录与产物 | 父任务快照及子任务实际执行信息 | 显示真实目录/共享关系；无法精确归属的改动只标“涉及文件”，不伪造独占 diff |
| 历史与导航 | 子事件嵌在父记录、现有任务链接 | 在父链接附子任务定位；刷新恢复、来源失效/记录不全提示，不把子任务改成独立普通任务来绕过 |

落点：`internal/web/page/agents.js`、`runs.js`、`chat.js`、`follow.js`、`util.js` 和面板布局；后端按需要修改 `internal/agent/subagent.go`、`subcontrol.go`、`internal/appserver/live.go`、`handle.go`、`internal/web/server.go`。改包前读对应 AGENTS。协议增量另写实现 spec，本次 IDL Diff 仍为无。

## 7. 验收与范围

以下定义完整验收场景，已执行的局部证据见 [实现记录](08-implementation.md)。使用真实子 agent 和真实浏览器；不以返回一个固定“完成”字符串代替并发、等待与恢复验证。

| 验收 ID / 批次 | 场景 | 通过标准 |
| --- | --- | --- |
| A23 / B2 | 同时有前台与后台子任务，后台 spawn 先返回而任务仍运行 | 启动回执不标完成；分工与数量准确；完成后状态一致 |
| A24 / B2 | 默认独立上下文、fork 继承、旧历史缺少模式信息 | 分别显示真实模式/未知；不固定写“看不到父对话”；无虚构继承范围 |
| A25 / B2 | 一个子任务等审批，一个正常工作，父 agent 等待结果 | 主待处理区定位准确、审批只作用目标、等待与运行并存、不遗漏兄弟任务 |
| A26 / B3 | 同 task_id 续跑/取回存档，查看结果并往返父子视图 | 一个逻辑子任务含多次尝试；不重复计数；结果有来源、回收不冒充采用；阅读位置保留 |
| A27 / B2–B3 | 父轮结束、连接中断、迟到终止事件、页面刷新 | 原因和未知态真实；事件重放不重复通知；没有后台常驻假象 |
| A28 / B4 | 直接补充、只停止其中一个、与完成并发、两个页面重复操作 | 目标及回执正确；父任务可见干预；兄弟任务继续；无重复执行，停止确认可靠 |
| A29 / B3 | 多个子任务读写共享目录，结果冲突或一项失败 | 显示共享关系；不把同一改动重复计为独占产物；父汇总能追到每个结果及未解决项 |
| A30 / B3–B4 | 窄屏、长任务名、切换子任务草稿、过期深链接、失败后续跑 | 导航清楚、草稿不串；链接失效可回父任务；恢复沿用正确身份且明确副作用边界 |

首版 B2/B3 包含协作可见性、状态准确、来源、导航和结果；B4 再完成网页直接干预与恢复。先改善用户已经反馈的日常体验，不将全部问题延期到完整多 agent 调度平台。全局 agent 管理中心、自动再派发、跨父任务迁移和跨轮常驻不在本期。

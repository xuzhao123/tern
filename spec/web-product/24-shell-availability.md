# 完全访问与命令工具可用性修复

2026-10-29。真实日常环境的platform.bash为off；最近的full+host任务快照和模型工具列表均没有bash。权限档位与工具启用是两件事，完全访问不会自动覆盖明确关闭的工具。

- 增加显式 `thread/bash/enable`（POST `/runs/{id}/enable-bash`），只在可管理的空闲普通任务启用命令；不启动模型、不改权限/执行位置、不改写旧轮次。先审计，再保存任务meta的bash_enabled，重复请求幂等。运行中、导入、评测试次拒绝。
- `thread/list` 返回bash_enabled，网页在命令未启用时解释原因，提供“为本任务启用命令”。任务后续启动把显式启用纳入新的工具快照；旧实例工具列表保持不变。设置页改默认开关不再被误解为能修改既有任务快照。
- 人的 `!` 命令带当前选择的permission/sandbox，服务端校验并按本次选择执行；旧客户端不传时继续沿用任务最新轮次。仅已启用命令的任务可运行，不能通过传host绕过工具关闭。首次启用且旧轮次没有沙箱ID时，以真实第一轮checkpoint ID确定会话临时目录。
- 新任务显式传入host时，bash可用性按最终执行位置重算；不因平台默认沙箱缺少bwrap而错误去掉宿主命令，也不把明确off自动改成on。
- 日常用户命令需求的配置修复使用settings/write，仅为实际登录账号打开bash；旧任务通过上述显式启用修复，不给其他账号改默认，不改权限和当前轮次。

验收：隔离QA关闭bash后真实模型确认无该工具；启用不增加轮次，后续真实模型实际执行宿主命令并得到工作目录；!命令显式host使用真实路径，sandbox仍进隔离环境；不同模式、非法值、未启用工具拒绝、请求去重、配置和任务meta跨重启持久化。构建、JS语法和真实页面操作后再同步日常服务；不在日常数据中启动测试模型或测试命令。

## 自动切成无人值守的根因与修复

用户补充“开始是完全访问，对话后自动变成无人值守”。前端runs.js在start/continue把事件的sandbox=host写入r.sandbox，又在turn/started把协议的sandbox（会话沙箱目录ID）写入同一属性；shell.js据此回显权限时，UUID不是host，full被显示为无人值守。下一条消息的permChoice还会把这个错误回显编码成full+sandbox，造成实际执行降档。

前端保留r.sandbox作为目录ID（文件预览仍依赖它），增加r.sandboxMode只保存start/continue的执行位置。权限回显只读sandboxMode；turn/started不改执行位置。旧记录缺模式继续按sandbox解释，不能推断升为host。真实验收覆盖完全访问首轮/续轮/刷新，以及用户明确切回无人值守；两者均保持自己的值。纯事件回归直接运行真实reducer，防止同名字段再次混用。

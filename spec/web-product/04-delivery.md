## 必须先定的数据与协议增量

本次文档本身 **IDL Diff：无**。下表为未来设计必答项，名字/存储格式尚未冻结，不能按这里的概念名误调用不存在的 API。

| 能力 | 当前可复用 | 需补充的契约 |
| --- | --- | --- |
| 项目身份 | workspace 登记、name/path、任务目录快照 | 稳定 ID、重命名不变、同主机同目录归一；旧任务用明确的同主机目录证据关联，歧义保留“历史项目”，禁止只凭同名合并 |
| 置顶/个人视图 | `.meta.json`、现有 settings 机制 | 置顶是账号偏好还是共享元数据：推荐账号偏好；不能把协议 `user` 字段当身份凭证，web 认证后注入 |
| 草稿 | 本地存储 helper、图片引用 | 账号/主机/任务键、版本、配额失败、退出清理/隔离、附件过期、多标签冲突 |
| 可靠发送/队列 | steer client_id、server queue、turn start | 普通发送去重与查询、未采纳 steer 持久化、队列原子领取、编辑/排序版本冲突；所有重试不能重复副作用 |
| 浏览器恢复 | server 订阅事件与序号、appclient 重连 | browser SSE 错误恢复、序号去重、审批/状态补齐、旧服务无能力时的降级 |
| diff 范围 | workspace/diff、copy_base、review 命令 | 范围类型、base revision、返回版本、旧/新行号、截断/二进制/重命名；最近一轮需要可靠数据源 |
| 文件引用/反馈 | @ 路径、沙箱文件、现有消息 | 服务端受限读取、主机+任务+相对路径、行范围与版本、引用失效、作为用户上下文传递 |
| Git 写入 | 执行主机上的现有仓库 | 目标仓库验证、busy/并发版本检查、操作结果/未知状态、审核范围、冲突恢复与审计 |
| 子 agent 协作 | 子任务事件、task_id、父 agent 的 wait/send/stop/fork | 稳定身份与尝试、等待/结果回收/实际上下文元数据；网页直控须补目标校验、协议转发、回执、审计与恢复，详见子 agent 专项 |
| 日常工作流补充 | 搜索、通知、用量/压缩、Skills、命令、文件和浏览器等现有基础 | EXT-01–09 的资源/引用版本、活动游标、操作实例、预览控制、Goal 调度等逐项契约，详见 07 的实现落点 |

项目迁移采用加字段兼容，不覆盖历史事件；先保存可恢复副本，做 dry-run 映射报告，无法唯一映射的任务继续可读可续聊。旧客户端仍按 name/path 和旧链接工作。涉及 app-server 协议版本的变化必须遵守现有兼容约束，不为新 UI 直接断开运行中的旧 agent。

### 工程验证方式

- 静态检查：按仓库要求执行 `gofmt -l .`、`go vet ./...`、`go build ./...`；对改动 JS 做 `node --check`。仅文档批次不需要跑程序构建。
- 行为验证：用真实模型、真实浏览器和真实测试仓库/SSH/MCP，不以 mock 成功替代真实链路。不可在日常 `~/.tern` 上做破坏性验收。
- VM 的临时 `TERN_HOME` 放在 ext4 自有目录，避免共享挂载里的运行 socket 问题；源代码 clone 可以在共享工作目录。只清理本批自有测试数据。
- UI 验证：保存上述视口截图，逐项检查可见行为；不能以 DOM 存在替代视觉和键盘验收。没有跑过的场景保留“待执行”。
- 完成判定：需求 ID → 实现提交 → 验收 ID → 证据文件可追溯；旧能力回归和异常流程都通过。不要以模型最后一句“做完了”作为完成证据。

## 发布与回退

先在独立运行目录用新 UI 验收，保留旧可执行文件及迁移前数据副本。纯布局批次可先发布；需要新协议的功能检查服务端能力后开放，旧后端显示能力不支持与升级指引。不能降级成语义不同的操作，例如请求“最近一轮”却展示整个仓库。

草稿/视图偏好必须可忽略或带版本兼容；持久数据迁移只做可回退的增量，不删除旧字段。回退时保留新增任务与用户输入，不能简单还原旧数据备份覆盖新写入。web 更新沿现有启动流程执行，自动换进程不是本方案附带实现。

## 尚待产品定稿的选择

| 选择 | 推荐默认值 | 影响 |
| --- | --- | --- |
| “一致”到什么程度 | 核心流程一致 + 接近的信息架构；视觉细节以新线框定稿 | 若要求像素级一致，需固定 Codex 版本和参考界面，再做设计稿 |
| 主导航术语 | 任务 / 项目；对话用于消息内容 | 仅文案，不改底层 thread/workspace 名称 |
| 模型切换 | 首版说明限制并另开任务，后续支持每轮换模型 | 避免为界面先行改历史和模型工具兼容 |
| Git 操作范围 | 首版只读评审和反馈；下一批文件级暂存/提交 | hunk、push、PR 不并入首版 |
| 浏览器还是完整 IDE | 首版工作面板只读文件 + 反馈 | 编辑器、完整终端需要单独交互设计 |
| 偏好跨设备同步 | 首版草稿与未读在本浏览器、账号隔离 | 后续同步需要账号级服务端契约 |

这些是待评审建议，不代表要一次提出六个阻塞问题。按当前推荐即可形成各批实现设计，影响范围较大的选择在相应批次开始前定稿。

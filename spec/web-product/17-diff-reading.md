# 改动阅读：行号、文件跳转与预览版本

状态：开发中，对应 WORK-02/03。四种 Git 范围已实现并通过25项累计真实 API/Git 检查；行反馈已进入实现与页面验收。初始阅读坐标增量和当前契约如下；不得据此关闭完整 A14/A15。

- 对统一 diff 的每个 hunk 分别计算旧侧、新侧行号；删除行只占旧侧，新增行只占新侧，上下文占两侧。文件头、二进制说明、无换行标记不是代码行，不伪造行号。现有未跟踪文本的新增内容从新侧第 1 行开始。
- 文件可通过“打开当前文件”进入同一工作面板的项目文件标签；它读取当前文件，不把旧侧内容或删除位置冒充当前源码。
- `workspace/diff` 兼容增加 `view_version`，是响应中目录、基准与已显示文件内容的 SHA-256，用于比较两次预览是否相同。它不是整个 Git 仓库的锁或事务版本，也不能证明未显示内容不变。旧客户端忽略此字段。
- 默认比较语义保持兼容，现已提供下节四种真实范围、重命名前后路径与二进制信息；没有完整快照来源时，最近一轮范围不能冒充精确差异。
- 行反馈引用范围、比较基准、左右侧、路径、行号、片段与预览版本，并先作为草稿；内容变化后标过期。不能仅用行号组件或保存按钮宣称整个反馈流程完成。

验证：纯解析检查多 hunk、增删/上下文、无换行、未跟踪文本与元信息；真实 Git diff 与浏览器阅读对照，文件跳转不得执行模型或改文件。进度与证据记入 08。

## 比较范围与反馈实施契约

延续 `GET /runs/{id}/diff` → `workspace/diff`，增加可选 `scope`、`base`。默认保持 `workspace`，非法范围返回400；新网页必须核对响应的范围，不把旧服务忽略参数的结果当成新范围。所有查询只读，不暂存、提交或运行外部 diff/textconv。

| scope | 左侧 → 右侧 | 未跟踪文件 |
| --- | --- | --- |
| workspace | 普通任务 HEAD → 当前工作目录；副本 copy_base → 当前副本目录 | 包含 |
| unstaged | 暂存区 → 当前工作目录 | 包含 |
| staged | HEAD → 暂存区 | 不包含 |
| branch | base 与 HEAD 的共同祖先 → HEAD；base 必须明确填写并解析为提交 | 不包含 |

未有首次提交时，用当前 Git 对象格式计算空树作为 workspace/staged 基准，不把暂存和未暂存的 patch 拼接成一份。副本基准缺失、无共同祖先、无效引用必须明确报错，不悄悄换成HEAD。返回 `scope`、`base_ref/base_oid`、`target/target_oid`、实际分支、每个文件的 `old_path/binary/truncated/notice/version` 和整份 `view_version`。重命名保留两侧路径；二进制不显示假的0行改动；大文件、总量或文件数超过预览上限时明确说明截断。预览版本只覆盖实际返回的内容，不是整仓锁或原子快照保证。

反馈操作先在所选文件/代码行旁填写意见，再保存为反馈草稿；保存、改写、删除都不运行模型或修改Git。草稿按账号、主机、任务隔离保存，切范围仍保留。引用必须携带比较范围、基准提交、左右侧、两侧路径、行号、片段、文件预览版本与意见。并行编辑不能静默覆盖原意见。

“加入输入”先重新读取相关范围，标记内容变化、文件消失或无法核对；过期意见保留原始定位和片段，不套用到新代码行。结果追加到已有主输入，保留文字与附件，用户实际发送后才交给agent。反馈历史继续可查看；不把“加入输入”显示为“已发送/已解决”。

验收补充：真实 Git fixture 覆盖暂存/未暂存/两者叠加、已暂存重命名、中文/空格/字面路径、二进制、未跟踪/符号链接、首次提交前、分支提交、无效基准与预览截断；UI验证选行、编辑/删除/刷新恢复、切范围、文件变化后过期、先入草稿而非立即执行。没有提交证据前本段仍为实施契约，不是完成声明。

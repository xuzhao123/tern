# 持续 Goal 与计划清单实现契约

2026-10-28。对应 EXT-09/CHAT-07 与 A40–A42/A21。普通 goal 文字提醒保留；新增显式持续执行状态，不从目标文字自动开启。

## 事实源与协议

- app-server 的 runMeta 增加 continuous_goal 和 plan，均采用版本化不可变副本原子保存。历史轮次、普通 goal 不改写。所有启动、用户排队、Goal续轮由现有 turnMu 与队列领取记录串行化。
- `thread/continuous/get|update`：读取；显式 start/pause/resume/modify/end 操作。更新带当前 revision，开始要求非运行任务、目标、约束及至少一条完成标准。预算可选，修改/恢复不清零累计用量。
- Goal 状态：running/pausing/paused/waiting_user/blocked/exhausted/completed/ended。结束保留记录；主任务“停止当前轮”先暂停 Goal，不能随后自动续轮。
- `task_status` / `report_goal` 是仅 app-server 启动的主 agent 拥有的工具，经原父进程协议连接访问所属任务；不信任模型传 user/threadId，不向子任务继承。报告携带 goal id/revision/current turn，由服务端核验，旧目标的报告不能完成新目标。
- 每个Goal自动轮次正常结束后只有当前目标版本的 continue 报告才可继续。自动轮次缺报告或连续无进展进入 blocked；普通用户队列轮不强制报告Goal，但运行中的Goal预算仍覆盖该轮。blocked、等待、预算耗尽、手动暂停不会自动恢复。
- complete 报告必须覆盖每一项完成标准，带可定位的真实成功工具调用证据及说明。服务端校验调用存在且成功，缺失/未知/失败证据不能完成；UI列出标准和证据供复核。模型仍负责判断证据与标准的语义，不把存在一条调用说成独立人工验收通过。

## 仲裁与恢复

- Goal 续轮作为带 goal id/revision 的内部队列项持久认领，复用 queue_id→启动事件的去重。用户已确认的队列项优先；暂停的用户队列不会因 Goal 被偷偷解除。新目标版本使尚未派发的旧 Goal 项失效。
- 关闭浏览器不暂停运行。进程重启先接管现存轮次并核对队列 claim；结果不明停在可核对状态，不把进程消失当成未执行重做。元数据写盘失败不继续派发。
- 子任务沿原有父轮生命周期，不为 Goal 自动延长或复制子任务。

## 预算

- 轮次上限按已持久认领的 Goal 续轮累计；未设置显示未设置，并保留100轮系统防空转上限。
- 时间是启动后累计的墙钟预算（含等待与暂停，UI明确），到期禁止新动作并请求当前轮中断；暂停/恢复不重置开始时间。
- token预算按主任务、子任务和辅助调用的供应商已报告用量累计。开启 token 上限时，同一任务的模型请求串行经过预算闸门：以完整请求UTF-8字节及协议开销作为保守输入上界，收紧输出token上限，不足时不发请求。图像/未知用量或不能确保输出限制的协议必须明确阻塞，不能用估算值冒充精确费用/额度，也不能悄悄扩预算。实际消耗与限制分别展示。

## 计划

- 复用已有 todo 清单结构，独立版本化 plan 状态包含步骤 pending/in_progress/completed/blocked、说明和批准版本。
- `update_plan` 只更新计划，不授予写文件权限。生成/修改方案保持 plan 权限，界面“开始实施”先明确本次将采用的权限，再作为正常用户消息启动下一轮；旧版本批准不能批准新计划。计划与普通目标/持续Goal分别呈现。

## 文件与验收

新增 appserver 的 Goal/plan拥有者、agent主任务工具定义与协议路由、网页Goal/plan面板。更新现有 runMeta、summary、notes、followUp、停止路径与模型代理预算检查；不复制新的调度进程。真实模型验证跨轮、版本修改、暂停/重启、队列优先、缺证据拒绝、预算和无报告停止，不新增Go mock测试。

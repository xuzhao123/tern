# 子任务提问、来源与请求取消

状态：开发中，覆盖 SUB-06、SUB-02、CHAT-04 的提问闭环；不等于所有审批和子任务直控已完成。

## 契约

- 父任务已启用 ask_user 时，派出的子 agent 继承该开关；父任务关闭时不新增能力。命令行/评测/队列默认仍无此工具。仍只允许一层子 agent，不增加嵌套派发能力。
- 父进程转发 user/requestInput、tool/requestApproval、network/requestApproval，并保留原始 call_id 为 original_call_id。转发用 task_id + 原始调用 ID 的稳定哈希生成 call_id；等待表与网页提交使用这个带子任务身份的键。工具轨迹与审计仍使用原始 ID，通过明确映射关联，不按同名/相同问题猜测。旧浏览器页面需刷新加载新前端才能完整显示带身份隔离的子任务请求；旧 agent 的未隔离请求仍按原路径兼容。
- 网页答复携带当前事件 request_id（event:<seq>），服务端认领时在同一把锁内校验版本；旧请求即使和新尝试复用了调用 ID，也不能答到新尝试。旧客户端未携带该字段时保留原行为。
- 回答只沿当前转发链返回原请求。父 agent 看不到用户答案作为新指令，也不能替用户回答。返回答案中的文字不会被解释成授权。
- 子进程取消请求或退出，转发等待随之取消。交互请求的 Call 取消时发送 request/cancelled 通知，参数 id 为此连接上原请求的 RPC ID；服务端只删除该 ID 对应的等待。普通 turn/start 等命令不因调用方超时而自动撤销。
- 可重连协议会从尚待答复集合移除已取消请求，避免接管重发。取消通知与原始事件保留在序列中；新客户端处理 input_closed，旧客户端仍能按原事件读历史，需升级才能及时呈现取消状态。协议版本不改。
- 请求取消与回答竞争时，以服务端先认领的等待项为准；取消已生效后回答返回 409。已经回答的请求不再生成失效事件。联网白名单原有对话级授权范围保持，不能把此变更宣称为单子任务网络隔离。
- 主对话待处理区与子任务详情显示真实来源；提问、审批状态独立于 spawn 回执。已结束/已取消的提问不再出现输入控件。关闭页面不会自动取消请求；服务重启后接管有效等待。

## 文件与验证

main.go 继承开关；agent/child.go 请求命名空间与取消链；protocol/protocol.go 仅交互请求的取消通知/待答复清理；appserver/server.go 清理权威等待并记录 input_closed；page/runs.js 保持父子状态引用、sandbox.js/chat.js 按来源关联控件、activity.js 统一来源呈现。

按仓库约束做 Go 格式/vet/build、JS 语法；真实模型同时派两个提问子任务，检查两个不同 task_id、原调用映射、独立答案和主任务汇总。另用真实子任务提问后停止/取消，检查等待清除和迟答 409；运行中重启隔离服务后检查有效请求身份及可回答性。无模型脚本替代，不新增 Go 测试文件。

## 真实验收发现的恢复修正

后台注册表原先只要存在同 task_id 就拒绝派发，即使 done 已关闭；父任务因而无法在本轮续跑被中断子任务。改为仅拒绝仍运行的实例，终止实例可原位替换，再交给 RunChild 的检查点判断续跑或结果回放。稳定身份与新实例的等待/停止路由一致，兄弟实例不受影响。网页对未真正启动的续跑失败保留上次真实生命周期，另显示派发失败，不用工具错误覆盖已停止/已完成状态。此修正对应 SUB-08 的恢复基础，不代表网页直控和所有恢复路径已完成。

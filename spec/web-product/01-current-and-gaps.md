# 功能现状与体验差距

基线：`6fba4ad`。本表保存立项时的产品需求与现状，不是缺陷复现报告，也不是实时开发状态。代码核对和 8090 页面观察的边界见 [证据](05-evidence.md)。当前实现进度与验收证据统一见 [实现记录](08-implementation.md)。

类型：**重组**＝已有能力调整入口/呈现；**增强**＝已有基础但需补行为；**新增**＝已检查的相关入口/协议未提供；**保留**＝不因对齐而删除。P0 为核心工作流，P1 为常用补强，P2 为后续候选。批次决定实际先后，P1 不意味着必须进入首版。

## 子 agent 协作体验

用户已明确反馈此处体验不足，因此不只作为 WORK-08 的一个标签处理。新增 **SUB-01–08**，分别覆盖分工总览、状态/等待、结果回收、父子导航、直接干预、审批来源、上下文/目录边界、续跑恢复。完整现状、P0/P1 与批次清单统一在 [子 agent 专项](06-subagents.md#2-新增需求清单)，避免在两处维护重复状态。

优先核验后台启动成功被当作完成、fork 模式仍显示“看不到父对话”两条静态发现；新增可见性与导航列入首版 B2/B3，网页直控列入 B4。

## 补充的日常工作流

上一轮补漏核查的 9 类已全部转为 **EXT-01–09**：命令面板与快速导航、活动中心、上下文与用量、显式 Skill、项目常用操作、网页预览批注、产物预览批注、多资源标签、Goal 持续模式。现状基础、目标行为与优先级维护在 [补充方案](07-workflow-completeness.md#1-范围与需求清单)，实现状态统一见 [实现记录](08-implementation.md)。不将已有用量环、压缩展示、Skills 中心、浏览器画面等重新算作“完全没有”。

## 当前能力必须保留

已有图片、Markdown/代码/数学展示、探索折叠、复制/导出、搜索、归档、分叉/旁支/撤销、长期记忆、Skills、MCP OAuth/资源、权限/沙箱、观测/评测/审计、多主机都不因新界面而被悄悄移除。低频能力可以换入口，必须有可找到的迁移路径。

## 不在首版承诺内

| 能力 | 处置 |
| --- | --- |
| 云执行、账户同步、跨设备通知/未读 | 新平台能力，当前浏览器未读本地保存；不能由侧栏改版顺带宣称支持 |
| 自动化、插件市场、语音/桌面控制 | 保留为候选，先核实用户真实需要与服务依赖 |
| 多目录项目、项目移动、真 worktree/Handoff | 需要目录权限、历史关联和 Git 生命周期设计，列 B5 |
| 全面 Codex 视觉复刻 | 本期提供布局与组件规格；没有素材/版本基线的细节标待定，不凭想象记成 Codex 行为 |

最终是否“体验接近”由关键流程验收判断，不能用旧的 40 项完成率或本表按钮数量替代。

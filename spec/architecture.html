tern 架构：三层进程（界面 → app-server → agent）

一个 Go 模块、一个入口 main.go。界面随人开关，app-server 常驻管对话，agent 一轮一个进程真正干活； 运行数据都在 TERN_HOME/.data/（TERN_HOME 没设时是 ~/.tern）。 详细说明见 architecture.md。

① 界面用户直接接触的三种入口随人开关，不持有对话

浏览器internal/web

  • 登录 cookie、页面（page/ 原生 ES 模块）
  • HTTP 接口 → 协议方法；事件流 SSE
  • 多主机 /h/<别名>/、内置计算器 MCP

终端internal/chat

  • 交互输入、斜杠命令
  • /fork <n>、/rewind <n>
  • 流式输出、运行中插话

一次性 CLIqueue / eval / metrics / audit / rewind / -question

  • 不经 app-server，直接读写 .data/
  • 队列与评测试次：每个任务一个子进程
HTTP（登录 cookie、SSE）｜终端标准输入输出　▼
② 连接层internal/appclient界面侧不启动 agent、不读写 .data 里的对话

连哪条路

  • 本机：.data/app-server/control.sock（Unix socket，目录 0700）
  • 远程：ssh -T <别名> 'exec "$SHELL" -lc "tern app-server proxy"'
  • 远程用 ssh 的 stdin/stdout 当协议通道：不开端口，鉴权就是 SSH

说什么、断了怎么办

  • 一行一条 JSON-RPC：initialize、thread/*、turn/*、approval/respond、settings/*
  • 退避 1、2、4…秒（最多 30 秒）重连；按最后收到的 seq 重新 thread/resume 补齐
  • Start：socket 连不上就后台起一个；发现旧 build 且自己更新，就换掉它
control.sock（本机）｜ssh → 远端的 app-server proxy → 远端 control.sock　▼
③ 常驻服务tern app-server一个 TERN_HOME 一个；internal/appserver

协议入口server.go

  • thread/start · fork · rewind · resume
  • turn/start · steer · interrupt
  • approval/respond、settings/*、files/*、hub/*（Skills、MCP）、eval/*

对话与设置archive · settings

  • 存档 runs/<对话ID>.jsonl：start、通知、request/response、approval、exit
  • 设置 settings.json：内置 › 平台 › 个人
  • hub.json：登记的 Skills 与 MCP

生命周期live · launch

  • 每轮用 /proc/self/exe -agent-server 起进程，进程号与令牌记 live/<ID>.json
  • 连上 agent 发 session/attach + turn/start
  • 自己重启后 adopt 接管还在跑的 agent；有评测在跑时不换 build

模型代理llm.sock

  • 校验 X-Agent-Token，按 X-Agent-Upstream 转发
  • 请求、响应记成存档事件；Authorization 只透传不记录
  • app-server 重启后，agent 的模型请求在这里等代理回来（最多 10 分钟）

审批与订阅hub · subscribe

  • approval、user/requestInput 推给所有界面，先到先得
  • 人的决定先写审计，再答复 agent
  • item/delta 只推正在看的界面，不进存档

附件·文件·评测·导入attachments · eval · import

  • 图片按内容寻址，消息里只放 attachment://
  • 评测试次、pass^k、归因与回放
  • 导入 Codex rollout 与 Claude Code 会话 JSONL
⇅ 下行：AGENT_APP_SOCKET=live/<对话ID>.sock，session/attach + turn/start 　⇅ 上行：模型请求走 AGENT_PROXY_SOCKET（llm.sock）
④ 执行进程tern -agent-server一轮一个进程；app-server 重启照常跑，由新的接管

执行循环react · dispatch · approval

  • 请求模型 → 执行工具 → 结果回填 → 下一步
  • 独立工具并发（默认 4）、分类重试
  • 高风险确认、重复动作与无进展熔断

上下文与恢复context_manager · checkpoint

  • Transcript / View、超预算结果进 outputs/
  • 压缩与摘要；每轮新检查点，用 continues 串成续接链
  • 撤销 rewind；会话记录 sessions/ 供补齐

工具（全在进程内）

  • workspace：read_file / write_file / edit_file / glob / grep，边界 os.Root；permission、hooks、commands
  • sandbox bash（bubblewrap，每对话一个目录）+ netguard 联网审批
  • browser、websearch(ds_search)、mcp、skills、memory / retrieval、read_output

模型客户端internal/llm

  • Chat Completions、Anthropic Messages、Responses 三种协议
  • 路由表（供应商 → 模型）、重试、上下文窗口
  • 请求经 llm.sock 交给 app-server 的代理

子 agent 与子进程subagent · child

  • spawn_agent 再起一个 tern -agent-server
  • 父子之间走同一套协议（标准输入输出）
  • 任务队列、评测试次也经 RunChild 起子进程

一轮怎么收尾

  • 写检查点 → 退出，app-server 记 exit 并删 live/ 里这一轮的三个文件
  • 续聊是下一轮：再起一个 agent，带上之前各轮与 continues
  • 没人连回来超过 10 分钟：中断、写好检查点、退出
外部服务与宿主资源

模型服务（app-server 转发）

  • 方舟 Ark（Coding Plan 入口）
  • DeepSeek（Chat 与 Anthropic 接口）
  • Coconut（Responses 协议，本机服务）

agent 进程内直连

  • 无头 Chrome / Chromium：open_page
  • bubblewrap + cgroup：bash 沙箱
  • netguard 代理：白名单外的域名要人批准
  • MCP server（子进程或 HTTP）、ds_search / ds_fetch
  • 向量模型：方舟线上，或本地纯 Go MiniLM

可观测

  • OpenTelemetry span → .data/traces/
  • OTLP 另发给 Jaeger 等平台
数据.data/（TERN_HOME，默认 ~/.tern）

app-server 写

  • app-server/：control.sock · llm.sock · pid · lock · log
  • runs/<对话ID>.jsonl：界面看到的一切
  • settings.json · hub.json · eval/

agent 写

  • live/<对话ID>.{sock,json,err}：正在跑的这一轮
  • checkpoints/ · sessions/ · outputs/
  • sandbox/<对话ID>/：bash 工作目录，续聊各轮共用
  • memory.json · memory-index/

共用

  • attachments/：图片按内容寻址
  • audit/audit.jsonl：只追加、哈希链
  • traces/ · users.json · web-hosts.json
一轮的链路：用户问题 → 组织上下文 → 请求模型 → tool_calls → 执行工具 → 结果回填 → 下一轮或结束。工具结果标来源，不当作新的授权。
断开时谁接着谁：界面 ↔ app-server 由界面退避重连、按 seq 补推；app-server ↔ agent 由新 app-server 读 live/*.json 接管，agent 补发之后的消息。
远程：界面在本机，对话、agent、代码、模型密钥都在远端；同一条协议走 ssh 的标准输入输出，所以远程、本机代码路径完全相同。

# 网页端输入框上方的待发送区：排队与插话的样式

状态：已实现（2026-11-01），在 `web-sidebar-polish` 分支上，未提交。只改显示，不改排队、插话的服务端逻辑和按钮的行为。

## 为什么要改

待发送区（`#steer-strip`，`index.html:84`，在输入框的框里、文字框上面）由 `composer.js` 的 `renderSteers` 画，里面依次是：受管插话（`managed-steer.js` 的 `managedSteerSection`）、旧版插话、排队（`queue.js` 的 `queueSection`）。在浏览器里把几种状态直接写进页面内存（不碰服务端）截了图，问题是：

| # | 现象 | 原因 |
| --- | --- | --- |
| 1 | 每条排队消息右边四个带边框的大按钮（编辑、上移、下移、删除），比文字还显眼；三条消息就是十二个按钮 | `.qactions button`（`app.css:879`）`padding:6px 9px`、1px 边框，常显 |
| 2 | 按钮和文字上下对不齐：文字贴顶，按钮在下面一截 | `.qitem` `align-items:flex-start`，按钮比文字行高 |
| 3 | 标题“这一轮结束后发（3）”和下面的消息同样的字号颜色，分不出哪个是标题 | `#steer-strip` 统一 12.5px `--muted` |
| 4 | 待发送区和下面的输入框连在一起，看着像输入框里已经有字 | 中间没有分隔，也没有底色区别 |
| 5 | 暂停时同一件事说两遍：红字“上一轮未正常结束，队列已暂停”，下一行“队列已暂停（1），不会自动发送” | `queueError` 单独一行，标题又按 `queuePaused` 写一遍 |
| 6 | 插话前面显示成“⊠” | `#steer-strip .item::before { content:"↳ " }`（`app.css:305`），字体里没有这个字，画成方框 |
| 7 | 插话和排队长得一样，只靠标题文字区分 | 同样的 `.head` / 文字样式 |
| 8 | 排了很多条时整块无限变高，把对话往上挤 | `#steer-strip` 没有高度上限 |
| 9 | 待发送区的文字比输入框里的提示文字往右缩了一截（30px） | `#steer-strip` 的 `padding:12px 16px 0` 加上外层的内边距 |

## 改成什么样

```
┌───────────────────────────────────────────────────────────┐
│ ↪ 插话 · 做完这一步后发给 agent                 [立即发送] │
│   用 go 1.23 的写法                                        │
│ ◷ 排队 · 这一轮结束后发 3 条                               │
│   1  跑完以后把 README 里的安装步骤也更新一下    ✎ ↑ ↓ ×   │ ← 悬停才出现
│   2  再检查一下 internal/web 下面有没有没用到的 import…    │
│   3  最后提交，提交信息写中文                              │
│ ───────────────────────────────────────────────────────── │
│ 继续提问                                                   │
└───────────────────────────────────────────────────────────┘
```

1. **分区标题**：每一节一行标题，左边一个 14px 线条图标（插话用转折箭头，排队用时钟，受管插话同插话），后面“插话 · 说明”或“排队 · 说明”，12px，“插话”“排队”两个字 `--text` 字重 500，说明 `--muted`。右边是这一节的操作（立即发送、发第一条、继续全部、核对状态……），样式统一成小号文字按钮：12px、无边框、悬停 `--hover` 底，主操作（立即发送、继续全部）用 `--accent` 字色。
2. **排队标题的说法**：
   - 运行中：`排队 · 这一轮结束后发 N 条`
   - 已停、没暂停：`排队 · 等你发送 N 条`，右边“发第一条”“继续全部”
   - 暂停：`排队 · 已暂停，不会自动发送`，后面跟暂停原因（`queueError`，`--warn` 色）同一行；不再单独出一行红字。`queueError` 不是暂停原因（队列没暂停时）照旧单独一行 `--err`。
3. **每条消息**：一行，13px `--text`，前面序号（`--faint`，等宽数字）；超过一行省略，悬停 `title` 显示全文；“补充转入下一轮”的那种在序号后加一个小标签“补充”。消息行高 30px，悬停 `--hover` 底、圆角 6px。
4. **每条的操作**：编辑、上移、下移、删除换成 24×24 的图标按钮（铅笔、上箭头、下箭头、×），无边框，`--muted`，悬停 `--text` 加底；平时隐藏，悬停或键盘聚焦这一行时出现（`visibility`，行宽不变）；触屏（`hover:none`）常显。第一条没有“上移”、最后一条没有“下移”：用 `visibility:hidden` 占位，不显示灰掉的按钮。`aria-label` 照旧（“编辑第 1 条排队消息”……）。
5. **插话的消息**：和排队消息同一种行样式，没有序号和操作；前面的“↳”字符去掉（第 6 条）。受管插话每条的状态说明（`meta`）放在文字后面，`--muted` 12px；它的那些处理按钮（转入暂停队列、移除、知道了）用第 1 项的小号文字按钮。
6. **领取中 / 回执待确认**：各是一行，`--warn` 色的说明加右边的小号文字按钮，放在排队标题下面。
7. **和输入框分开**：待发送区底部一条 `--line` 分隔线，和输入框之间留 8px；左边和输入框里的提示文字对齐（去掉多出来的缩进）。
8. **高度上限**：待发送区最多 `min(40vh, 240px)`，超出在里面滚动；分区标题不吸顶（条数少时用不到）。
9. 深色模式只用变量，不另写。

图标：`util.js` 的 `ICON_PATHS` 加 `edit`、`up`、`down`、`clock`、`steer`（线条画，24 视口，与现有 `close` 同风格），用 `icon(name)`。

## 按文件的改动

| 文件 | 改动 |
| --- | --- |
| `internal/web/page/queue.js` | `queueSection`：标题拆成图标 + “排队” + 说明 + 操作；暂停原因并进标题；每条加序号、操作换成图标按钮（`action` 新增一个可选图标参数，或另写 `iconAction`），首尾的上移/下移改成占位隐藏 |
| `internal/web/page/composer.js` | `renderSteers` 里旧版插话那节：标题同样拆成图标 + “插话” + 说明；不改签名逻辑和“立即发送”的行为 |
| `internal/web/page/managed-steer.js` | 标题换成同样的结构（“插话 · 当前轮补充 N 条”）；不改按钮和状态逻辑 |
| `internal/web/page/util.js` | `ICON_PATHS` 加五个图标 |
| `internal/web/page/layout.css` | 新的一整块 `#steer-strip` 样式（以 `#steer-strip` 开头，压过 `app.css` 的旧规则）；`app.css` 的旧规则不删，这一期不清 |

不要改：排队、插话的任何请求和参数，版本号与冲突处理，编辑对话框（`#queue-dialog`），按钮的可用条件（`disabled` 的判断照旧，只是首尾的上移/下移从“灰掉”改成“不显示”）。

## 这一期不做

- 拖动排序：仍用上移、下移。
- 点一条展开看全文：先靠悬停 `title`；编辑对话框里本来就能看全文。
- 把待发送区挪到输入框外面：留在框里，只加分隔。

## 已定的问题（用户 2026-11-01 同意按建议做）

1. 每条的操作平时隐藏、悬停或聚焦这一行才出现。
2. 排队消息只显示一行，全文在悬停 `title` 和编辑框里看。

## 实现时的偏离

- 隐藏操作按钮用 `opacity:0`，不用 `visibility:hidden`：`visibility:hidden` 的按钮键盘 Tab 不到，“键盘聚焦这一行时出现”就做不到。首条的上移、末条的下移仍用 `visibility:hidden` 占位（`.qslot`）。
- 三处分区标题用同一个函数画，放在 `util.js` 的 `stripHead(icon, 名称, 说明, 原因)`，三个文件都引它。
- 受管插话的处理按钮放进每条下面的 `.msacts` 一行；原文用 `.mstext`，不用 `.item`（避免套上插话行的 30px 行高）。
- 领取中 / 回执待确认的提示行（`.qwarn`）可以折两行，因为恢复提示本身是一句长说明。

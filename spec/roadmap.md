# tern 重新规划

状态：草稿（2026-11-04）。第 1 期走查已做，第六节 A、B 组（第 1–10 项）已修，见第七节。

## 一、目标

用户自己用，用得爽，体验对齐 Codex 和 Claude Code。**主入口是网页端（用户 2026-11-04 明确）**，所以对标的是这两家的桌面端和网页端（Codex 应用、Claude Code on the web / desktop），不是它们的终端界面。

判断一个功能的标准只有两条：用户日常用不用；手感比那两家差多少。不追求多用户、不追求功能数量。

## 二、现状（2026-11-04，只看代码和实际运行）

**网页端的实测结果在第六节。** 总体：骨架和速度已经接近 Codex 应用，差距在几条主路径和大量暴露出来的内部状态。

**已知的事实（行数，不含测试）：**

| 部分 | 行数 |
| --- | --- |
| 网页端（`internal/web`：Go 2190，页面 11728） | 13918 |
| `internal/appserver` | 12002 |
| `internal/agent`（主循环） | 5179 |
| `internal/eval` | 2520 |
| `internal/chat`（终端） | 1124 |

`main.go` 有 74 个参数定义、10 个子命令。

**用量数据不能当证据：** 这台机器的 `~/.tern` 只有 6 条对话，没有一次 `edit_file`、`write_file`，当时也没有网页端在跑。用户的主要使用可能不在这份数据里，不据此下结论。

**底子：** agent 主循环、沙箱（bwrap、Seatbelt）、`apply_patch` 与撤销、权限规则、hooks、子 agent、MCP、skill、检查点续跑都已经有了。

**终端（次要入口）：** `tern chat` 不默认用当前目录（问目录里有什么，它看的是空沙箱）；裸 `tern` 只有 `read_output` 一个工具；工具调用打印截断的 JSON。记下来，不排进前几期。

## 三、分期（草案）

每一期做完，用户都要能用它干真实的活，不只是过测试。

### 第 1 期：走查，排出不爽清单

- 用户先说最不爽的几件事，这是最高优先级的输入。
- 按真实工作流走一遍网页端（开对话、选项目、读改代码、看 diff、审批、打断、插话、撤销、续聊、切换任务、长对话），和两家逐项对比，截图记录，分清“没有”“有但难用”“差不多”。
- 量几个硬数字：打开页面、发出第一条消息到第一个字、切换对话的耗时，长对话下的流畅度。

产出：写进这份文档的一张按痛感排序的清单。

### 第 2 期：修清单的前几项

一次一小批，每批用户用过再排下一批。

### 第 3 期：agent 本身的手感

响应速度、改代码的成功率、长对话的压缩、错误恢复。网页端再顺，agent 干活不行也不爽。具体项由真实使用暴露，不提前排。

### 第 4 期：瘦身

用不到的功能下线或挪走，参数减少。放在最后：等清单稳定了，才知道什么不再需要。

## 四、这一轮不做

- 不做多用户、多租户。
- 不做终端全屏界面。
- 不把评测当合并门槛（用户已取消）；评测在怀疑模型行为变差时手动跑。

## 五、需要确认的问题

1. 网页端目前最不爽的是哪几件事？
2. 用户平时在哪台机器上用（这台，还是 Mac 或 `-remote`）？走查要按真实环境来。
3. 默认模型用哪个？现在程序默认 `ark`，实际常用 DeepSeek。“对齐那两家”也受模型能力限制，要不要接 Claude、GPT？
4. 哪些功能已经确定不用，可以提前砍（多租户、队列、记忆、RAG、审计、指标……）？
5. `AGENTS.md`、`CLAUDE.md` 要重写：“只有 Claude 写设计、tern 实现”“不写 mock 模型”这些流程规则还要不要？这些文件每次会话都会加载，不改的话旧流程还会继续生效。

## 六、第 1 期走查结果（2026-11-04）

环境：这台 Linux，无头 Chrome，临时 `TERN_HOME`，项目是 tern 的临时 clone，模型 DeepSeek flash。用户平时用 Codex，以它为标尺；这台机器上没有装 Codex 应用，对比依据是对它的了解和本地的 Codex 源码，不是并排实测。

### 已经够好，不要动

| 项目 | 实测 |
| --- | --- |
| 真实编码任务 | 给 `glob` 补表格测试：22.5 秒改完并跑通，沙箱外复跑 `go test` 也通过 |
| 切换对话 | 48–124ms |
| 运行中刷新页面 | 352ms 恢复，任务继续 |
| Esc 打断 | 84ms |

| 其他 | 整体布局、工具行摘要、改动卡片、diff 面板、`/` 菜单、`@文件`、审批卡片、深色模式、窄屏 |

### 按痛感排序的问题

**A. 会让任务白跑或反复打断**

1. 新任务默认“无工作区”。刚添加完项目，输入框仍是无工作区；点项目行只会折叠它（“新任务”藏在悬停才出现的 `⋯` 里）。结果任务发到空沙箱，模型回答“找不到代码”。应该：添加后自动选中，新任务默认上次的项目，点项目行就在里面新建。
2. 审批只有“允许一次”，没有“以后都允许”（Codex 有）。一个追加一行 README 再编译的小任务要点 3 次。
3. 只读命令也要批：模型习惯写 `cd /workspace && git status`，而 `internal/permission` 的只读名单里没有 `cd`，整条被判成非只读。

**B. 把内部状态直接给人看（看着不专业，也增加理解成本）**

4. 主动停止被展示成错误：红字“已按停止按钮中断：已取消（context canceled）”，按的是 Esc 也这么说，下面还有“检查点已保存”“最后几行输出”“完整终端输出”。应该只有安静的一行“已停止”。
5. 模型错误原样输出：右上角 `model_error`，正文是带 request_id 的 API 报错。余额不足应该直说“DeepSeek 余额不足”并给出下一步。
6. 插话区：“核对状态”“停止并发送未采纳内容”“补充已由服务端接收，采纳结果见待发区”。
7. 每轮开头都有一行“Skills 1/1”，还有一行没有内容的“思考”。
8. 浏览器标签页标题是 `tern · <UUID>`，不是任务名。
9. “上次预览 · 2 个文件已更改”的“上次预览”看不懂。
10. 设置页带着多层继承的概念：“保存为我的设置”“恢复继承”“保存为平台默认”“设置怎么生效”，这些是给多用户用的。

**C. 细节**

11. `@文件` 匹配太散：搜 `perm` 会列出一堆无关的 spec 文档。
12. diff 没有语法高亮，长行被截断，要横向滚动。
13. 完成和审批的通知默认关闭，切走了就不知道要处理。
14. 没有直连 Claude、GPT 的供应商（第五节第 3 问）。

### 这次没测到

长对话（模型余额用完，拿副本也没能加载，所以渲染压力和压缩都没量）；撤销、分叉；子 agent、MCP、图片；`-remote` 和多主机；macOS。用户说机器都会用，第二轮走查要补 Mac 和远程。

## 七、第一批修复（2026-11-04，用户要求 Claude Code 直接改）

| 项 | 改了什么 | 验证 |
| --- | --- | --- |
| 1 | 添加项目后自动选中；新任务默认上次的项目（按主机记在浏览器里，选过“无工作区”也记）；没记录且只有一个项目时用它；设置里定了默认工作区优先。点项目名就在里面开新任务，展开收起留给左边的箭头 | 无头 Chrome 实测 |

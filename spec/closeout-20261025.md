## 本次修正

原验收留下的 10 项修正已核对：未发送目标的清除语义、副本 diff 文案、命令卡片刷新、输出前导空格、命令并发限制、项目配置及下拉同步、MCP 资源外发标记、只有资源的 MCP、Mac 回环隔离及图片路径。

收尾中另发现并修复：

1. **Mac 沙箱无法启动。** Seatbelt 不接受 `127.0.0.1:<端口>`，所有命令均报 `host must be * or localhost in network address`。策略改用 `localhost:<端口>`，HTTP 代理仍使用实际监听地址。
2. **新远端无法首次复制密钥。** 读取尚不存在的 `.env` 返回非零，导致写入前直接失败。仅把不存在视为空配置；已有文件不可读仍拒绝覆盖。读写与 proxy 使用同一个登录 shell 的 `TERN_HOME`，未设置才取 `~/.tern`。
3. **副本改变未跟踪文件的性质。** 脚本被写成 0644，符号链接被展开成目标内容。改用 `Lstat` 保留权限和链接，避免把工作区外的内容读进副本。

## OAuth 补充验收与验证边界

- **MCP OAuth：** 使用官方 Keycloak 26.4.0 容器、独立 realm 和预注册的 public client（PKCE S256），MCP 服务逐次向 Keycloak introspection 校验令牌、issuer、audience 和过期时间。真实浏览器验证错误密码拒绝、正确登录、回调、防重放；等待访问令牌自然过期（30 秒），确认旧令牌被服务拒绝，Tern 自动刷新、刷新令牌轮换并落盘。真实 DeepSeek 调用受保护的 `whoami` 返回正确身份；退出删除本地令牌，重新连接要求授权。没有修改令牌到期时间，没有伪造授权服务器响应。
- 本次覆盖预注册 public client；动态注册沿用此前的协议验证，不把它算作本次 Keycloak 实测。退出验证的是客户端清理本地令牌，未宣称退出 Keycloak SSO 或撤销服务端整个授权。任意第三方 OAuth 服务的兼容性仍需分别验证。
- 测试环境独立于用户日常 `~/.tern`，位于 VM 的 `/home/dev/.tern-oauth-lab`，只监听回环地址。Keycloak 是真实授权服务器，测试 MCP 工具仅返回测试身份，无业务数据。
- 没有修改用户个人 Claude Code/Codex 的持久 MCP 配置。`tern mcp-server` 已用实际 stdio 客户端验证；是否接入个人客户端由用户选择。

# 改前面的问题，重新发

状态：已实现（2026-10-24，tern 实现；Claude Code 用真实模型和无头 Chrome 驱动真实页面验收）。验收时发现改第 1 轮用不了（全部撤销后不能续聊），已改成全部撤销后在同一条对话里重新开始。

## 1. 为什么要改

问错了、问得不清楚，想改一下前面某句话重新来，现在要分三步：点那一轮的“撤销”（`internal/web/page/chat.js:345`，只有带工作区的对话才有），在对话框里选怎么退，确认以后再到输入框里重新敲一遍问题。没有工作区的对话连“撤销”都没有。

Codex 的 TUI 按两下 Esc 回到上一条自己的消息，改完直接发出去，后面的作废（`codex-rs/tui/src/app_backtrack.rs`）；协议里对应 `thread/revert`。

## 2. 改什么

- **按钮**：每一轮的问题下面，在“撤销”“分叉”旁边加“编辑”。显示条件和“分叉”一样（对话已经停下、不是导入的、不在回放、这一轮有检查点、没被撤销过、不是分叉时带过来的；`chat.js:351` 那个条件），**不要求有工作区**。
- **对话框**：复用撤销对话框（`#rewind-dialog`，`shell.js:425` 的 `rewindTurn`），加一种“编辑重发”的用法：
  - 标题“改第 n 轮的问题，重新发”。
  - 多一个文本框（`#rw-text`，平时藏着），里面是这一轮原来的问题，打开时光标放进去。
  - 三种退法照旧，默认“文件和对话一起退”。没有工作区的对话只能“只退对话”，另外两项灰掉。预览照旧显示要恢复、删除的文件和冲突。
  - 按钮文字“撤销并重新发”。文本框是空的、或者和原来一字不差又选了“只退对话”时，按钮也能点（就是原样重问一遍）。
- **确认以后**：
  1. 先按选的方式撤销（`POST /runs/<id>/rewind`，`dryRun: false`），失败就把错误显示在对话框里，不关；
  2. 成功后用文本框里的内容续聊（`POST /runs/<id>/messages`）。权限模式、推理强度取输入框旁边当前的选择（和平时续聊一样），附图不带；
  3. 关掉对话框，打开这条对话（`show(r.id)`）。
  撤销成功、发送失败时：对话框关掉，文本框的内容放进页面的输入框，`#hint` 显示“没发出去：<原因>”，内容不丢。
- 原来的“撤销”按钮和行为不变（不带文本框）。

### 验收时发现：改第 1 轮（2026-10-24）

撤销到第 1 轮之前以后，这条对话一轮都不剩（`rewind` 事件的 `continues` 为空）。`canContinue` 这时返回 false（`internal/appserver/server.go:1244` 的注释：“连第一轮也撤销了，就没有可以接着的对话”），续聊被拒，所以编辑重发在第 1 轮上用不了。改成：
- `canContinue`：全部撤销掉（撤销过、`lastCheckpoint()` 为空）时返回 true，意思是“可以在这条对话里重新开始”；
- `turn/start`：遇到这种情况不带续接（不传 `-continue`、不给续聊上下文），照这条对话 start 事件里的快照（工具、工作区、模型），像新对话一样起第一轮。检查点、沙箱目录都是新的（第一轮的 ID 变了）；
- 页面上编辑第 1 轮和编辑别的轮一样，不用特殊处理。

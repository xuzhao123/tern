# edit_file 对不上原文时：只差空白就照改，真对不上就给出最接近的原文

状态：已实现（2026-10-24，tern 实现；Claude Code 用真实模型验收）。

## 1. 为什么要改

`edit_file` 要求 `old_string` 和文件里的原文一字不差（`internal/workspace/workspace.go:488` 的 `editFile`，用 `strings.Count`）。对不上就只回一句“old_string 在 … 里没有找到；检查空格、缩进与换行…”。2026-10-23 实现第一份 spec 时，tern 有 4 次编辑因为 gofmt 对齐过的空白没对上而失败，每次都要多花几轮去 `read_file` 看原文。之后几次实现也反复出现。

Codex 的 `apply_patch` 找原文时一级一级放宽：先精确匹配，再忽略行尾空白，再忽略首尾空白，再把几种 Unicode 标点当成一样（`codex-rs/apply-patch/src/seek_sequence.rs`）。只差空白的改动照样能落下去。

## 2. 改什么

### 2.1 精确匹配不到时，逐级放宽

`old_string` 在文件里一次都没出现，并且不是 `replace_all` 时，按行比较，一级一级放宽：

1. 每行忽略行尾空白（`strings.TrimRight(line, " \t")`）；
2. 每行忽略首尾空白（`strings.TrimSpace`）；
3. 每行去掉首尾空白以后，行内连续的空格和 Tab 当成一个空格（gofmt 对齐结构体字段、注释时最常见的就是这种）。

做法：
- `old_string` 按 `\n` 切成行（结尾的空行去掉）。在文件的每个起点上，比较连续同样行数的那一段：用同一级的规则把两边各行规整以后，逐行相等就算这一级的一处匹配。
- 从第 1 级开始，哪一级先有匹配就停在那一级。
- 那一级**正好一处**：把文件里这一段原文（整行，从这段第一行的行首到最后一行的行尾）替换成 `new_string`，结果里加 `"matched": "忽略行尾空白"`（或者“忽略首尾空白”“忽略行内空白的多少”），并照常给 `first_line` 和 `diff`。这样模型知道是按宽松规则改的，回头可以看一眼缩进对不对。
- 那一级**不止一处**：不改，报错“old_string 按<规则>在 … 里匹配到 N 处（第 a、b 行），多带几行上下文让它唯一”。
- 三级都没有：进 2.2。

不放宽的情况：`replace_all=true`（批量替换必须精确，不能顺手改到不该改的）；`old_string` 只有一行、而且规整以后是空串。

### 2.2 都对不上：给出最接近的原文

报错里附上文件里最像的一段，让模型直接照抄：
- 候选：文件里所有和 `old_string` 行数相同的窗口。打分：窗口里按第 3 级规整以后和 `old_string` 对应行相等的行数。取分数最高的，同分取最靠前的。
- 分数为 0（一行都对不上）时，退一步找 `old_string` 第一个非空行：规整后在文件某行里出现（子串）的，取第一处，窗口从那一行开始。
- 还是找不到，就只回原来那句话，加一句“先用 read_file 看一下这个文件现在的内容”。
- 附的格式和 `read_file` 的输出一样（`行号\t内容`），最多 12 行，前面说明“文件里最接近的是第 a–b 行（N 行里有 M 行对得上）：”。

### 2.3 不变的

- 精确匹配到一处、多处（`replace_all` 或报“出现了 N 次”）的行为不变。
- 改之前要 `read_file`、文件被别人改过就拒绝（`fresh`）、写前快照、受保护文件这些检查都在放宽匹配之前，照旧。
- 工具说明（`workspace.go:74` 的 description）补一句：只差空白时会按宽松规则匹配，并在结果里注明；对不上时会给出文件里最接近的原文。

## 4. 这一期不做

- Codex 第 4 级的 Unicode 标点规整（全角半角引号、各种破折号）。
- 跨行的空白差异（比如原文一行，`old_string` 折成了两行）。
- 改完以后自动按文件原来的缩进风格（Tab/空格）重排 `new_string`。

## 5. 验收

### tern 自己做（不需要真实模型，在沙箱里）

1. `gofmt -l .` 没有输出；`go vet ./...`、`go build ./...` 通过。
2. 在仓库里建一个临时目录（比如 `tmp-editcheck/`，验完删掉，不要留在工作区）放一个 `main.go`：`workspace.Open` 一个 `/scratch` 下的临时目录，里面写一个 gofmt 对齐过的 Go 文件，用 `workspace.Run` 先 `read_file` 再 `edit_file`，逐条报告结果：
   - `old_string` 精确：照旧改，没有 `matched`；
   - 行尾多了空格：改了，`matched` 是“忽略行尾空白”；
   - 用空格代替了 Tab 缩进：改了，`matched` 是“忽略首尾空白”；
   - 结构体字段的对齐空格数不一样：改了，`matched` 是“忽略行内空白的多少”；
   - 放宽以后匹配到两处：不改，报“匹配到 2 处（第 …行）”；
   - 完全写错的一行：不改，报错里有“文件里最接近的是第 …行”和带行号的原文；
   - `replace_all=true` 加空白差异：不放宽，照旧报“没有找到”。

网页操作用户本机的代码

用户在自己的机器上运行 tern connect，主动连上我们部署的网页端。之后在网页上发起的对话交给他本机的 tern 执行：读写文件、跑命令都发生在他的机器上，网页只负责显示过程和让人审批。思路同 Claude Code 的 Remote Control。

一条向外的连接
用户本机不开端口；断线重连后，正在跑的对话接着显示。
密钥只在服务器
用户不需要自己的模型密钥，模型请求经服务器的代理加密钥转发。
本机有上限
只动登记的目录、权限模式有上限、bash 一律进沙箱，服务器改不了。

01tern 的几种界面

agent 只有一个；下面这些是它的界面，都经同一套 app-server 协议与它通信。

中文命令或形态是什么
命令行tern一次一个任务，适合脚本
终端tern chat终端里的多轮对话
网页端tern web浏览器里用，可以部署给别人（以前叫观测台）
桌面端单独的应用（以后）装在本机，窗口里用

连接器 tern connect 不是界面：它把本机目录接到网页端，在本机执行任务，就是这份设计要做的东西。

桌面端以后做时和这份设计的关系：桌面端本来就跑在用户机器上，只用本机时它就是本地的网页端；连上服务器时，它同时承担连接器的角色。所以连接器的逻辑放在 internal/connect 包里，tern connect 只是一个薄的命令行入口，桌面端以后直接复用这个包。网页端的页面也会被桌面端复用，页面里不要写死“一定部署在服务器上”这类假设（比如登录这一步）。

02用户怎么用

  1. 网页设置 → 本机连接 → 新建连接，起个名字（如“笔记本”），拿到只显示一次的令牌。
  2. 本机运行 tern connect，列出允许 agent 使用的目录。
  3. 网页新对话 → 工作区下拉里出现“笔记本：app” → 提问。
  4. 本机终端逐行显示这条对话在做什么；Ctrl-C 停止全部对话并断开。
  5. 网页本机连接 → 吊销，令牌立即失效，连接断开。
$ tern connect -server https://tern.example.com -token tk_••••••• -dir ~/code/app -dir ~/code/lib
已连接 · 账号 alice · 目录 app、lib · 权限上限 edit
[对话 3f2a · app] read_file internal/agent/react.go
[对话 3f2a · app] edit_file internal/agent/react.go
[对话 3f2a · app] bash go test ./...   → exit 0
[对话 3f2a · app] 结束 · 6 次模型请求

终端输出是示意。-dir 可以写多次，目录名默认取最后一段，重名时写 -dir app=~/code/app。只有列出的目录会出现在网页上。

03架构

两台机器之间只有两条连接，都由用户这一侧发起。控制连接是一条 WebSocket：启动、停止对话，以及把每条对话的 app-server 协议消息原样来回转发。模型请求和现在本机 agent 经网页端代理一样，只是地址从 http://127.0.0.1:8090 换成服务器的 https 地址。

04变的是哪一跳

现在网页端和 agent 之间已经全部经 protocol.Conn 交互，只有“起进程”和“Dial 本机 socket”这两件事要求两者在同一台机器上。远程对话把这两件事交给连接器，中间多出一跳 wss。

05一次远程对话怎么跑

停止

第一次按停止，网页端经协议发 turn/interrupt，和现在一样。再按一次强制结束：本地对话是向进程组发 SIGKILL，远程对话改发 run/stop {force: true}，由连接器结束进程组。

续聊

网页端照旧从自己的存档还原上一轮的消息：模型请求都经过它的代理，存档里有完整的请求与回答。中途被停下的对话第一期也用存档还原（agent 会给没有结果的工具调用补“结果未知”），第二期再从连接器取本机检查点。

06断线重连

连接器断网时，agent 子进程照常运行：它在本机 socket 上脱离，发出的消息按序号留在内存里，最多等 10 分钟（protocol.DetachGrace）。连接器重新连上后，网页端对每条还没结束的对话发 run/attach {after}，补发的消息经 wss 回来。这和网页端重启后接管本机 agent 是同一套机制。

07配对与鉴权

  • 连接令牌在网页“本机连接”里新建：32 字节随机数，只显示一次。服务器只存 SHA-256，放 .data/connectors.json（0600，不提交），连同账号、租户、名字、创建与最近连接时间。
  • 一个令牌对应一个连接器、属于一个账号。吊销即删除记录，正连着的立即断开；同一令牌再连一次，旧连接作废。
  • 连接只接受 wss://<服务器>/connect，Authorization: Bearer <令牌>，令牌不经明文。第一条消息是 connector/hello，核对后回 connector/welcome。
  • 只派自己的对话：网页端只把这个账号发起的对话派给它；按编号访问的接口照旧核对租户。
  • 租户账号要租户开通新功能 connect 才能建连接（同 workspace）；平台账号默认可以。

账号与连接器

  • 网页端仍然要登录。账号密码管的是“谁在用网页”，连接令牌管的是“哪台机器替这个账号干活”，两者不互相替代。令牌只能由登录后的账号在“本机连接”里创建，归这个账号所有；连接器不知道账号的密码。
  • 一个连接器只属于一个账号。同一台机器要给两个账号用，就跑两个连接器，各用各的令牌和数据目录。两边的检查点、快照、审计、沙箱临时目录互不相干，网页上各自只看到自己登记的目录。
  • 同一个目录两个账号都可以登记，但同时改同一份代码时看不到对方的改动：编辑前“读过的内容没变”的检查能拦下直接覆盖，拦不住逻辑上的冲突。不同账号最好用不同的目录或 git worktree。
  • 以后要一个进程服务多个账号，可以让 tern connect 接受多个 -token，每个令牌一个独立的数据目录；第一期不做。
$ TERN_HOME=~/.tern-alice tern connect -server https://tern.example.com -token <alice 的令牌> -dir ~/code/app
$ TERN_HOME=~/.tern-bob   tern connect -server https://tern.example.com -token <bob 的令牌>   -dir ~/code/lib

08控制连接上的消息

一行一条 JSON-RPC 2.0，和 app-server 协议同一种写法，两侧都复用 protocol.Conn。审批、提问、插话、停止都是 run/data 里的原有协议行，不需要新消息。

方向消息内容
连接器 → 网页端connector/hello版本、系统与架构；登记的目录（名字、git 分支，不含本机路径）；bash 是否可用；权限上限；正在运行的对话ID
网页端 → 连接器run/launch对话ID、目录名、过滤后的 agent 参数、模型代理地址与令牌、turn/start 的内容；回复 pid 或拒绝原因
网页端 → 连接器run/attach对话ID、after：重连后补齐
双向run/data对话ID 加一行 app-server 协议消息，原样转发，不解析
网页端 → 连接器run/stop对话ID、force：false 发 turn/interrupt，true 按进程组结束
连接器 → 网页端run/exit对话ID、退出状态（连接器看得到真实的退出码）
双向ping心跳，每 30 秒

09模型请求与密钥

现在的代理转发 agent 带来的密钥，发到 agent 在 X-Agent-Upstream 里声明的地址。对远程 agent 这不成立：用户机器上没有我们的密钥，也不能让它指定上游，否则它能把我们加上的密钥发到自己的地址。所以远程对话的请求里，agent 只说用哪家，地址和密钥都由服务器定。

  • agent 判断“经代理”的条件改成有 AGENT_PROXY_TOKEN，不再看地址是不是 http://127.0.0.1；代理模式下 llm.LoadConfig 不要求本机有密钥。
  • 用量照旧记在网页端的存档里，underQuota 照旧按账号限制同时运行的对话数。

10安全边界

连上就意味着用户允许这台服务器在他登记的目录里运行 agent。下面这些上限由连接器在本机执行，服务器（包括被攻破的服务器）改不了。

服务器传来连接器怎么处理
任意路径、../只认 -dir 登记的目录名，路径由连接器补；文件工具经 os.Root 限制在目录内
-permission-mode full降到本机上限 -max-permission（默认 edit）；要 full 得用户在本机显式写 -max-permission full
-hooks、-mcp-server一律丢掉：它们在用户机器上、沙箱外执行。本机 hooks 只来自 tern connect -hooks（第二期）
-bash一律在沙箱里（bubblewrap、seccomp、cgroup、断网、.git 只读、.env 换空）；本机没有 bubblewrap 就不提供 bash
-net-allow照用（来自这个账号自己的设置与审批）；本机给了 -net-allow-max 时只接受其中的域名
替用户点“允许”剩下的风险。加 tern connect -approve-locally 后，审批与联网请求改在本机终端由人确认，网页上的答复不算数（第二期）

留在用户本机

  • 代码本身
  • 检查点、编辑快照、会话记录、agent 的执行审计、沙箱临时文件，都在 ~/.tern/.data/

会到服务器上

  • 模型读到的文件内容：经代理发给模型供应商，并记进服务器的对话存档（页面、续聊、归因靠它）
  • 人的点击审计

“会到服务器上”的部分要在网页的“本机连接”页面上写明。

13分期与验证

第一期

配对与吊销、连接与重连、远程目录、发起与续聊、审批与提问、停止、模型代理加密钥、Linux 上的文件工具与 bash、子 agent。

第二期 第三期

第二期：撤销、沙箱文件面板、附图、检查点续聊、调用链、本机 hooks、-approve-locally。第三期：macOS 的 bash。

第一期怎么验证

用真实模型、两套环境：服务器跑网页端，另一台机器（或同一台机器上换一个用户和数据目录）跑连接器，在临时 clone 里做编码任务。

  • 正常编码任务：读、改、跑测试，改动出现在连接器那边的目录里；服务器上没有这份代码的拷贝（存档里的模型请求除外）。
  • 断网重连：对话进行中断开连接器的网络 30 秒，恢复后页面补齐中间的过程，对话正常结束。
  • 越权：服务器传 -permission-mode full、-hooks、-mcp-server、不存在的目录名、../ 路径，连接器拒绝或降级，并在本机终端说明。
  • 吊销：对话进行中吊销令牌，连接立即断开，agent 收尾写好检查点。
  • 密钥：连接器所在机器上没有任何模型密钥，对话照常；改写 X-Agent-Upstream 指向别的地址，服务器不转发。

14需要确认的问题

  1. Q1

    远程对话的模型请求要不要完整记进服务器存档？记的话页面、续聊、归因照常；不记的话代码片段不落服务器，但这些功能要改成从连接器取。

    设计按“记”写。

  2. Q2

    连接器的权限上限默认 edit，还是更保守的 ask？

    设计按 edit 写，和本地对话的默认一致。

  3. Q3

    租户账号能不能用？

    设计里需要租户开通 connect 功能。

  4. Q4

    -approve-locally（审批只在本机终端确认）放第二期是否可以，还是第一期就要？

    它防的是服务器被攻破后替用户点“允许”。

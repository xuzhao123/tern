# 网页端草稿：每次打开都误报“另一页面修改了这份草稿”

状态：已修复并验收（2026-10-31，用户要求 Claude Code 直接修，分支 `web-sidebar-polish`）。

## 现象

每次打开网页端，输入框上方都出现“另一页面修改了这份草稿。两个版本均已保留，请选择：”，即使只开了一个页面；点了“保留我的版本”，下次打开照样出现。

## 原因

草稿存在浏览器的 localStorage（`drafts.js`）：主记录 `tern-draft-v1:<账号>:<主机>:<task:ID 或 new:项目>`，每个页面另存一份 `…:copy:<页面ID>`。每条记录带 `ancestors`（它是在哪些版本之上改的，最新的在前）。打开页面时，某份副本既不是主记录、也不在主记录的 `ancestors` 里、内容又不同，就当作别的页面改过，提示冲突。

`persist` 里截取 `ancestors` 用的是 `slice(-64)`，留下的是最旧的 64 个。输入框每敲一个字保存一次，敲满 64 次以后，每次保存都把刚刚的上一版截掉；旧页面留下的副本从此认不出祖先，每次打开都报冲突。选版本时也走 `persist`，选中的那一版同样被截掉，所以选了也没用。

复现（Playwright，干净的浏览器存储）：第 1 页逐字输入 70 个字符，第 2 页改一个字，第 3、4 页打开都出现提示；第 3 页选“保留我的版本”后第 4 页仍出现。

## 改动

| 文件 | 改动 |
| --- | --- |
| `internal/web/page/drafts.js` | `persist`：`slice(-64)` 改为 `slice(0, 64)`，保留最新的 64 个祖先 |
| `internal/web/page/drafts.js` | `initDrafts` 开头一次性清理 `cleanStaleCopies`：对每个 `…:copy:…`，有主记录且副本写入时间不晚于主记录的删掉（已被主记录取代）；比主记录晚的（冲突时另存的本页输入）和没有主记录的保留。清理完写标记 `tern-draft-v1-copies-cleaned`，之后不再执行；读不了存储时不清理也不写标记 |

代价：如果清理前恰好有两个页面同时改过同一份草稿、又都没选版本就关掉了，较早的那份会在这次清理中删掉。这种情况下用户看到的本来也是被误报淹没的提示，接受。

不改：冲突的判断规则、三个选项、页面之间的 `storage` 事件同步、发送后清空草稿的逻辑。

## 验收记录

用 Playwright 连现有网页端、把 `/ui/drafts.js` 换成工作区或 HEAD 的版本，每个场景一个干净的浏览器存储：

- 新代码按复现步骤：第 3、4 页打开都没有提示，副本只剩 1 份。
- 先用旧代码造出误报（第 3、4 页都有提示，副本 3→4 份），再换新代码：第 1、2 次打开都没有提示，副本剩 2 份（冲突时另存的、内容与主记录相同），清理标记已写，输入框里的草稿还在。
- 真冲突仍报：两个页面同时输入同一份新任务草稿，先被覆盖的那页出现提示；两页都关后再打开仍提示，直到选择版本。
- `node --check internal/web/page/drafts.js`、`go build ./...` 通过。
